01 · Outcome

这节课只完成一条最小链路

用户要求读取项目说明。模型先返回 read_project_brief 工具请求；你的应用执行只读工具， 把结果交回同一次调用；模型得到资料后给出最终回答。

看得见的完成标准

在 projects/web-creation-agent-workbench/ 中运行 npm test，四条关键路径通过；运行 npm run demo， 终端按顺序显示用户输入、模型请求、工具调用、工具结果和最终回答。

这正好对应 Learning Record 0003 记录的能力空白。你已经会 React 和 TypeScript，因此本课不复习语言基础， 重点是第一次亲手控制 Agent 的数据流和结束规则。

为什么先不用真实模型？

真实模型会带来网络、密钥、费用和输出变化。第一次写循环时，这些变量会让你难以判断： 问题来自循环，还是来自模型这次恰好换了一种回答。

所以本课使用可控假模型：提前写好第一轮和第二轮返回什么。 它不模拟智能，只让同一条测试每次得到相同结果。等循环通过测试后， 后续 Lesson 再把它替换为真实的 Responses-compatible Model Profile。

03 · Basics

Agent 不是“更会聊天的模型”

一次普通模型请求是：应用发送内容，模型返回文字。Agent 多了一条能力： 当模型缺少资料或需要执行动作时，它可以先返回一份结构化工具请求。 应用执行工具，再把结果放进下一次模型请求。

问题 普通模型请求 Agent 循环
模型返回什么？ 通常直接返回文字。 可能返回文字，也可能请求工具。
应用做什么？ 发送一次请求并显示回答。 执行工具、保存结果，再次请求模型。
何时结束？ 一次响应完成后结束。 最终回答出现，或触发应用的结束规则。

先分清四个参与者

参与者 负责什么 不负责什么
用户 提出目标：“读取项目说明并总结。” 不需要指定代码如何执行。
模型 决定直接回答，还是请求某个已开放工具。 不亲自运行本地 TypeScript 函数。
应用程序 调用模型、检查请求、执行工具、保存上下文、决定何时结束。 不允许模型绕过工具清单执行任意代码。
工具 接收明确参数并完成一个小操作。 不决定下一步是否继续调用模型。
最重要的一句话

模型只提出工具请求；真正执行工具的是你的应用程序。

一个可靠的最小循环需要五样东西

  1. 会增长的上下文。 第二轮不只发送工具结果，还要保留用户输入和第一轮工具请求。
  2. 工具清单。 模型只能请求应用明确开放的工具，应用按名称找到对应函数。
  3. 参数检查。 arguments 来自模型，执行前必须解析并验证。
  4. 清楚的结束规则。 没有工具请求且已有最终回答时，循环结束。
  5. 最大轮次。 如果模型一直请求工具，应用必须主动结束运行。

04 · Walkthrough

用一个任务走完五个动作

用户输入：

读取 demo-landing-page 的项目说明，并告诉我它为谁服务、要达成什么目标。
  1. 应用发送用户目标和工具清单
  2. 模型返回工具请求
  3. 应用检查参数并执行工具
  4. 应用交回工具结果
  5. 模型返回最终回答

动作 1：应用把目标和工具清单发给模型

工具清单告诉模型：你可以请求 read_project_brief， 它只接受一个字符串参数 briefId。此时工具还没有运行。

动作 2：模型提出工具请求

{
  "type": "function_call",
  "call_id": "call_001",
  "name": "read_project_brief",
  "arguments": "{\"briefId\":\"demo-landing-page\"}"
}

这不是最终答案。它的意思是：“应用，请用这些参数执行这个工具。”

动作 3：应用检查参数并执行工具

应用先把 arguments 从 JSON 字符串解析成对象， 确认 briefId 是字符串，然后调用本地函数。 

{
  "ok": true,
  "data": {
    "version": "v1",
    "audience": "独立开发者",
    "goal": "收集候补名单"
  }
}

动作 4：应用把结果交回同一次调用

{
  "type": "function_call_output",
  "call_id": "call_001",
  "output": "{\"ok\":true,\"data\":{\"version\":\"v1\",\"audience\":\"独立开发者\",\"goal\":\"收集候补名单\"}}"
}

call_id 必须保持为 call_001。 它相当于取件号：模型可以知道这份结果属于哪一次工具请求。

动作 5：模型根据真实资料回答

这个落地页服务于独立开发者，目标是收集候补名单。

第二轮没有新的工具请求，并且已有最终文字，所以应用结束循环并把回答交给用户。

05 · Protocol

只记住本课真正会用到的字段

字段 谁产生 用途
type: "function_call" 模型 说明这条输出是工具请求，不是最终文字。
name 模型 应用用它在工具清单中找到对应函数。
arguments 模型 JSON 字符串；应用解析并检查后才能执行。
call_id 模型 把一次请求与稍后返回的结果配对。
type: "function_call_output" 应用 把工具的成功或失败信息放进下一次模型请求。
output 应用 通常是字符串；本课使用 JSON 字符串。

OpenAI 官方文档说明，response.output 可能含有零个、一个或多个 function_call；每条调用包含 call_id、 name 和 JSON 编码的 arguments。应用执行后， 以同一个 call_id 返回 function_call_output。 详见 Handling function calls 。

本课有意缩小协议范围

真实 Responses 输出还可能包含 message、reasoning 等其他项目。 本课的 ModelClient 只暴露循环需要的 function_call 和 output_text。 后续接入真实 Provider 时，再由适配层处理完整响应。

参数错误为什么不直接让程序崩溃？

“参数不是合法 JSON”或“缺少 briefId”是模型可以理解并修正的信息。 应用把它包装成结构化工具结果，模型下一轮就能解释失败或重新请求； 如果直接抛出未处理异常，整次运行会在模型得到反馈之前中断。

export type UserInput = {
  role: "user";
  content: string;
};

export type FunctionCall = {
  type: "function_call";
  call_id: string;
  name: string;
  arguments: string;
};

export type FunctionCallOutput = {
  type: "function_call_output";
  call_id: string;
  output: string;
};

export type InputItem =
  | UserInput
  | FunctionCall
  | FunctionCallOutput;

export type FunctionToolDefinition = {
  type: "function";
  name: string;
  description: string;
  parameters: Record<string, unknown>;
  strict: true;
};

export type ModelResponse = {
  output: FunctionCall[];
  output_text: string;
};

export interface ModelClient {
  respond(
    input: readonly InputItem[],
    tools: readonly FunctionToolDefinition[],
  ): Promise<ModelResponse>;
}

Step 3 · 建立一个只读工具和工具清单

目标：只允许模型读取一份固定项目说明； 参数错误变成清楚的 JSON 结果。

新建文件：src/tools.ts

import type {
  FunctionCall,
  FunctionToolDefinition,
} from "./protocol.js";

type Tool = {
  definition: FunctionToolDefinition;
  execute: (argumentsJson: string) => string;
};

function isRecord(value: unknown): value is Record<string, unknown> {
  return typeof value === "object" && value !== null;
}

const readProjectBrief: Tool = {
  definition: {
    type: "function",
    name: "read_project_brief",
    description: "读取一份已存在的项目说明；不会修改任何文件。",
    parameters: {
      type: "object",
      properties: {
        briefId: { type: "string" },
      },
      required: ["briefId"],
      additionalProperties: false,
    },
    strict: true,
  },
  execute(argumentsJson) {
    let parsed: unknown;

    try {
      parsed = JSON.parse(argumentsJson);
    } catch {
      return JSON.stringify({
        ok: false,
        error: {
          code: "INVALID_JSON",
          message: "工具参数不是合法 JSON",
        },
      });
    }

    if (!isRecord(parsed) || typeof parsed.briefId !== "string") {
      return JSON.stringify({
        ok: false,
        error: {
          code: "INVALID_ARGUMENTS",
          message: "briefId 必须是字符串",
        },
      });
    }

    if (parsed.briefId !== "demo-landing-page") {
      return JSON.stringify({
        ok: false,
        error: {
          code: "BRIEF_NOT_FOUND",
          message: `找不到项目说明：${parsed.briefId}`,
        },
      });
    }

    return JSON.stringify({
      ok: true,
      data: {
        version: "v1",
        audience: "独立开发者",
        goal: "收集候补名单",
      },
    });
  },
};

const toolRegistry: Record<string, Tool> = {
  [readProjectBrief.definition.name]: readProjectBrief,
};

export const toolDefinitions = Object.values(toolRegistry).map(
  (tool) => tool.definition,
);

export function executeTool(call: FunctionCall): string {
  const tool = toolRegistry[call.name];

  if (!tool) {
    return JSON.stringify({
      ok: false,
      error: {
        code: "UNKNOWN_TOOL",
        message: `未开放工具：${call.name}`,
      },
    });
  }

  return tool.execute(call.arguments);
}

import type {
  FunctionToolDefinition,
  InputItem,
  ModelClient,
  ModelResponse,
} from "./protocol.js";

export class FakeModel implements ModelClient {
  readonly requests: Array<{
    input: InputItem[];
    tools: FunctionToolDefinition[];
  }> = [];

  private readonly responses: ModelResponse[];

  constructor(responses: ModelResponse[]) {
    this.responses = [...responses];
  }

  async respond(
    input: readonly InputItem[],
    tools: readonly FunctionToolDefinition[],
  ): Promise<ModelResponse> {
    this.requests.push({
      input: [...input],
      tools: [...tools],
    });

    const response = this.responses.shift();

    if (!response) {
      throw new Error("假模型没有下一条预设响应");
    }

    return response;
  }
}

Step 5 · 先把循环写成流程骨架

目标：先自己把五个动作对应到代码位置，再查看完整实现。

新建文件：src/agent-loop.ts

操作提示：先不要展开答案，按下面顺序写出自己的版本：

  1. 建立 input 数组，先放入用户输入。
  2. 用 for 循环限制最多请求模型 maxTurns 次。
  3. 每轮把当前 input 和工具定义交给模型。
  4. 把模型返回的工具请求追加到 input。
  5. 没有工具请求时，检查并返回最终文字。
  6. 有工具请求时，执行工具并追加 function_call_output。
  7. 循环用尽后抛出包含最大轮次的错误。
自己尝试后，展开参考实现 
import type {
  FunctionCallOutput,
  InputItem,
  ModelClient,
} from "./protocol.js";
import {
  executeTool,
  toolDefinitions,
} from "./tools.js";

type RunAgentOptions = {
  model: ModelClient;
  userText: string;
  maxTurns?: number;
  onEvent?: (event: string) => void;
};

export async function runAgent({
  model,
  userText,
  maxTurns = 4,
  onEvent = () => {},
}: RunAgentOptions): Promise<string> {
  const input: InputItem[] = [
    { role: "user", content: userText },
  ];

  onEvent(`[user] ${userText}`);

  for (let turn = 1; turn <= maxTurns; turn += 1) {
    onEvent(`[model_request] turn=${turn}`);

    const response = await model.respond(input, toolDefinitions);
    input.push(...response.output);

    if (response.output.length === 0) {
      if (!response.output_text) {
        throw new Error("模型既没有请求工具，也没有返回最终回答");
      }

      onEvent(`[final] ${response.output_text}`);
      return response.output_text;
    }

    if (response.output.length > 1) {
      throw new Error("本课一次只处理一个工具请求");
    }

    const call = response.output[0];
    onEvent(`[function_call] ${call.name} · ${call.call_id}`);

    const output = executeTool(call);
    const result: FunctionCallOutput = {
      type: "function_call_output",
      call_id: call.call_id,
      output,
    };

    input.push(result);
    onEvent(`[function_call_output] ${call.call_id} · ${output}`);
  }

  throw new Error(`超过最大轮次 ${maxTurns}，运行已结束`);
}

运行：npm run check

import { describe, expect, it } from "vitest";
import { runAgent } from "../src/agent-loop.js";
import { FakeModel } from "../src/fake-model.js";

const toolCall = (
  callId: string,
  argumentsJson = '{"briefId":"demo-landing-page"}',
) => ({
  output: [
    {
      type: "function_call" as const,
      call_id: callId,
      name: "read_project_brief",
      arguments: argumentsJson,
    },
  ],
  output_text: "",
});

describe("runAgent", () => {
  it("执行工具并把结果交回同一次调用", async () => {
    const model = new FakeModel([
      toolCall("call_001"),
      {
        output: [],
        output_text: "服务于独立开发者，目标是收集候补名单。",
      },
    ]);

    const answer = await runAgent({
      model,
      userText: "读取项目说明并总结",
    });

    expect(answer).toContain("独立开发者");
    expect(model.requests).toHaveLength(2);

    const result = model.requests[1].input.find(
      (item) => item.type === "function_call_output",
    );

    expect(result).toMatchObject({
      type: "function_call_output",
      call_id: "call_001",
    });
  });

  it("参数错误时把错误结果交回模型", async () => {
    const model = new FakeModel([
      toolCall("call_bad_args", "{}"),
      {
        output: [],
        output_text: "缺少 briefId，无法读取项目说明。",
      },
    ]);

    await runAgent({
      model,
      userText: "读取项目说明",
    });

    const result = model.requests[1].input.find(
      (item) => item.type === "function_call_output",
    );

    if (result?.type !== "function_call_output") {
      throw new Error("第二轮缺少工具结果");
    }

    expect(JSON.parse(result.output)).toMatchObject({
      ok: false,
      error: { code: "INVALID_ARGUMENTS" },
    });
  });

  it("模型不请求工具时直接结束", async () => {
    const model = new FakeModel([
      {
        output: [],
        output_text: "你好，现在不需要读取项目说明。",
      },
    ]);

    const answer = await runAgent({
      model,
      userText: "你好",
    });

    expect(answer).toBe("你好，现在不需要读取项目说明。");
    expect(model.requests).toHaveLength(1);
  });

  it("达到最大轮次后结束", async () => {
    const model = new FakeModel([
      toolCall("call_001"),
      toolCall("call_002"),
    ]);

    await expect(
      runAgent({
        model,
        userText: "一直读取项目说明",
        maxTurns: 2,
      }),
    ).rejects.toThrow("超过最大轮次 2");

    expect(model.requests).toHaveLength(2);
  });
});

08 · Explain

合上代码，回答六个问题

  1. Agent 与一次普通模型请求的本质区别是什么？
  2. 模型请求工具后，谁真正执行 TypeScript 函数？
  3. 第二轮为什么要保留第一轮工具请求，而不只发送工具结果？
  4. call_id 解决了什么配对问题？
  5. 参数错误为什么应该作为工具结果交回模型？
  6. 最大轮次由谁设置？它避免了什么风险？
先独立回答，再展开核对

1. Agent 应用会在模型和工具之间重复传递请求与结果，直到完成或触发结束规则。 2. 应用程序执行函数，模型只提出结构化请求。 3. 模型需要完整上下文，才能知道结果来自什么请求以及用户原本要什么。 4. call_id 把一份工具结果与一次具体调用配对。 5. 清楚的错误结果让模型能够解释、修正或改用其他方案，也避免可预期输入错误直接中断运行。 6. 应用设置并执行最大轮次，防止模型不断请求工具形成无限循环。
