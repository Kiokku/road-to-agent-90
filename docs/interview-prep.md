# Web Creation Agent Workbench 面试准备

## 一句话项目说明

我用 React、TypeScript 和自建 Responses API Agent Loop，实现了一个受 Étiquette Style Profile 约束的网页制作 Agent：它能流式展示规划与工具执行，生成并预览单页 React 网站，支持对话修改、diff 和版本回退，并且只在用户明确批准后部署到 Cloudflare Pages。

## 5–10 分钟演示顺序

1. 用 30 秒说明“生成网页过程黑盒、工具风险不可见”的问题。
2. 选择已通过能力检查的 Model Profile，输入网页需求。
3. 展示 planning、tool call、observation 与 artifact 事件，而非只展示最终回答。
4. 打开真实构建预览，提出一次对话修改并审查 diff。
5. 拒绝一次高风险动作，说明批准与模型意图的区别。
6. 批准当前版本部署，展示 Cloudflare URL 与完整 trace。
7. 注入一次失败，展示确定终态、有限重试与错误证据。

## 高频追问

### Agent 与普通 LLM 请求的本质区别是什么？

普通请求以模型输出文本为终点；Agent Loop 把模型输出解释为受约束的工具调用，应用负责校验、执行、回填结果并决定是否继续。模型提出动作，运行时拥有权限和终止权。

### 为什么浏览器不直接调用模型？

API Key、Base URL、工具权限和运行状态必须由服务端持有。前端只选择经过能力检查的 Model Profile，并消费领域事件；否则密钥会暴露，且无法可靠审计和控制工具执行。

### 为什么不用 Agents SDK？

短期目标是亲手理解 function call、`call_id`、工具结果回填、重试和终止条件，因此直接实现 Responses Loop。未来若采用 SDK，我也能说明它替代了哪段机制以及带来的抽象代价。

### 为什么选择 SSE？

当前主要是服务端到浏览器的单向事件流，客户端动作仍可用普通 HTTP；SSE 简单、可观察且贴合需求。代价是断线恢复和副作用事件去重需要应用协议处理，不能把自动重连当成安全重放。

### Agent UI 最难的状态是什么？

不是 token 增量，而是运行、工具调用、批准、取消、失败和重试之间的状态一致性。每个 run 必须只有一个终态，重复或乱序事件必须可处理，副作用工具不能被无意重放。

### 如何安全支持自定义模型？

服务端维护 Model Profile：显示名、Base URL、Model ID、密钥环境变量和能力声明。Profile 必须通过 `/responses`、typed streaming、function calling、错误结构和取消测试后才可选，浏览器不接受任意 URL、模型名或密钥。

### 如何判断生成网页真的遵守设计规范？

把 Étiquette 风格固化为版本化 Style Profile，结合 token/结构检查、WCAG、390px/1440px 视觉验收和人工批准。失败项被记录为证据，不让模型自行宣称通过。

### 为什么部署必须批准？

部署会改变外部公开状态。预览成功只证明构建可用，不代表用户授权发布；批准还必须绑定具体版本，过期批准不能复用于后续修改。

### 如何知道 Agent 改版后变好了？

使用固定 eval cases 比较任务成功率、风格遵守、工具成功率、延迟、调用次数与失败分类，并保留人工视觉验收。单元测试验证确定逻辑，eval 衡量概率性系统的产品结果。

## 表达边界

- 不把作品描述成“聊天机器人”或“完整 Kimi 克隆”。
- 不把“OpenAI-compatible”直接等同于 Responses-compatible。
- 不声称 Packy Terra 的能力已经通过验证，直到真实 Token 的检查证据存在。
- 不说“AI 帮我写完了”；明确说明自己定义、验证和解释的状态契约、权限边界与失败路径。
