## 用五句话讲清 Agent Loop

1. 用户向应用提出“读取项目说明并总结”的目标。
2. 应用把用户输入和允许使用的工具定义交给模型。
3. 模型不执行工具，只返回带有 `name`、`arguments` 和 `call_id` 的 `function_call`。
4. 应用解析并校验参数、执行工具，再用相同的 `call_id` 把 `function_call_output` 放进下一次模型输入。
5. 模型根据工具结果给出最终回答；如果模型持续请求工具，应用在达到最大轮次后停止运行。

## 追问记录

### `call_id` 解决什么问题？

`call_id` 是一次工具请求的配对标识。应用返回工具结果时必须原样带回它，让模型能够判断结果属于哪一次调用；工具名称相同也不能代替调用标识。

### 为什么工具结果必须回填给模型？

模型只能提出工具请求，真正执行工具的是应用。若结果不进入下一轮输入，模型看不到成功数据或参数错误，就无法基于真实观察继续回答或修正请求。

### 为什么参数错误也作为工具结果返回？

缺少 `briefId` 等错误是模型可以理解和修正的运行信息。把它包装成结构化结果能保留循环；直接让未处理异常终止进程，会让模型失去修正机会。

### 如何避免无限循环？

结束权属于应用：没有新工具请求且出现最终回答时正常结束；模型持续请求工具时，由 `maxTurns` 强制停止并记录 `stopped`，不能让模型自行决定无限运行。

### Agent 与一次普通 LLM 请求的本质区别是什么？

普通请求通常以模型返回文本为终点。Agent Loop 会把模型输出解释成受约束的工具请求，由应用校验、执行、回填结果并决定是否继续。模型提出动作，应用拥有权限与终止权。
